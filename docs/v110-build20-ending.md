# ICE WOLF v1.1.0 Build 20 — 決着表示のバグ2件（調査と修正）

Build 19 の実機テスト（2026-11-19）で、トモアキさんから「時間も残っている・ゲートも
閉まっているのに**人間の勝利／時間切れで決着**になった」と報告がありました。雪山ロッジ
（18:52 の収録）と宇宙船（19:05 の収録）の2本で同じ症状が出ていたので、収録を1秒刻みで
解析し、`game.json` の決着に関わる全ブロックを追いました。

## 1. 症状（収録から確定した事実）

雪山ロッジ（`ScreenRecording_11-19-2026 18-52-12`、オフライン・あなた：人狼・1F）:

| 時刻 | HUD |
| --- | --- |
| 38s | 2:33 |
| 45s | 2:26 / 生存2・凍結3 / スイッチ2/3 / ゲート閉鎖中×3 / 人狼モード発動！ |
| 47.40s | **2:24** / 生存1・凍結3 / スイッチ2/3 / ゲート閉鎖中×3 |
| 47.47s | **人間の勝利／時間切れで決着**（結果画面） |

- タイマーは 38s→47s で 2:33→2:24 と**正常に1秒ずつ**減っていました。0:00 のフレームは
  1枚も存在しません。つまり**時間切れイベントは発火していません**。
- ゲート脱出なら `EscapeWonByGate` が立ち、表示は「ゲート脱出で決着」になるはずで、
  これも否定されます（表示は時間切れ）。
- 47.4s の HUD は「生存: 1」。この直後に最後の人間が凍結され「生存: 0」→
  **全員凍結＝人狼の勝利**が正しく成立していました（プレイヤーは人狼）。

宇宙船（`ScreenRecording_11-19-2026 19-05-08`、あなた：人間）:

- 1本目（30〜49s）は 2F のゲートが開き、人間の勝利で終了（この回の勝ち文が
  `人間の勝利` としてキャッシュされます）。
- 2本目（58〜89s）: 66s に罠「D は3人目の人狼になった」→ 79.6s に**あなたが凍結**
  （生存1／凍結4）→ 88.35s まで 2:27→2:26、スイッチ1/3、ゲート閉鎖中×3。
- 88.5s に **人間の勝利／時間切れで決着**。ここでも時間切れのフレームはありません。

## 2. 真因（フレームの実行順序）

**勝敗判定そのものは正しく、結果画面が「前のラウンドの勝ち文」を表示していました。**

1. HUDの12言語化パス（グループ `v1.0.0 HUD 多言語反映`、レイアウト上は20番より後）は、
   テキストオブジェクトごとに「最後に見た日本語の原文」をキャッシュし、
   `runtimeScene.__iceWolfHudSource('WinText')` で返します。
2. 結果画面（グループ `v0.6.5 Production Round Start + Main Menu`）は `GameOver` に
   なった瞬間にそのキャッシュから勝者を読みます。
3. しかし**全員凍結（`v0.6.5 Survivor/Frozen counter`）と時間切れ（`Wolf match flow`）は
   20番より先に実行される**ため、同じフレームで `WinText` を書き換えても、20番が読むのは
   パスがまだ更新していない**前ラウンドの原文**（＝前回の `人間の勝利`）でした。
4. さらに決着理由は「ゲートのフラグが立っていなければ、人狼以外＝時間切れ」という
   推測式だったため、実際は全員凍結なのに「時間切れで決着」と表示しました。

同じ理由で、**戦績カウント・効果音・オンラインのホストがゲストへ送る `winId`/`winBy`** も
前ラウンドの結果を拾う可能性がありました（ゲストの結果画面も同じように間違う）。

## 3. 修正

1. `__iceWolfHudSource` は**渡された時点の実テキスト**とキャッシュを突き合わせ、
   書き換えられていれば即座に新しい原文として返します（空文字は「まだ決着していない」）。
   これでどのグループから読んでも順序に依存しません。
2. 決着時に **`WinWinner`（wolf/human）と `WinReason`（frozen/time/gate）** を各決着箇所が
   明示的に書きます。

   | 決着 | 場所 | 書き込む値 |
   | --- | --- | --- |
   | 全員凍結 | `Wolf match flow`（HumanActive=0）と `v0.6.5 Survivor/Frozen counter` | wolf / frozen |
   | 時間切れ | `Wolf match flow`（MatchTimeLeft<=0） | human / time |
   | ゲート脱出 | `v0.7.0 2階・階段・5スイッチ・3ゲート` | human / gate |
   | オンライン | `v1.1.0 オンライン対戦同期`（ホストの `winId`/`winBy`） | ホストの値 |

3. 結果画面・戦績・効果音・ホストのスナップショットは、この2変数だけを見ます
   （`tests/pro/v111-endings.test.mjs` が読む `iceWolfEndingCopy`）。
   ラウンド開始（`resetRound`）で両方クリアします。

## 4. もう1件（同じ収録で見つかった別のバグ）

宇宙船の収録では、罠の警告「⚠️ 罠！「D」は3人目の人狼になった！」が **66秒から88秒まで
22秒間**、画面中央に出たままでした。

- `ActionFeedbackText` には自前の時計（`FeedbackLeft`）があり、`v0.3 Action clarity feedback`
  が0で隠します。
- しかしメニューグループが**毎フレーム** `ActionFeedbackText` を表示し直していたため、
  隠した次のフレームでまた出ていました（`WinText` も同じ一括表示の対象でした）。
- 修正：フィードバック行だけ `FeedbackLeft > 0` のときだけ表示するようにしました。

## 5. テスト

`tests/pro/v111-endings.test.mjs`（11件）:

- 前ラウンドが `人間の勝利` で終わった後、新しいラウンドで `人狼の勝利` を書いたフレームで
  `__iceWolfHudSource` が `人狼の勝利` を返すこと（**Build 19 ではここで失敗します**）
- 空文字は「前ラウンドの勝ち文」を返さないこと
- 12言語に翻訳されたHUDでも、記録・効果音は日本語の原文を読めること
- 4つの決着（wolf/frozen・human/time・human/gate・未決着）で、結果画面の見出しと
  決着理由が正しいこと
- 決着を書く場所がすべて `WinWinner`/`WinReason` を書いていること（新しい決着を
  足したときの取りこぼし防止）
- ラウンド開始で両方クリアされること
- 結果画面・戦績・効果音・ホストが推測ではなく決着モデルを読むこと
- フィードバック行が時計どおりに消えること（メニューグループが表示し直さないこと）
