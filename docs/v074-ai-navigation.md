v0.7.3（Build 5）の実機テストで、トモアキさんから

> でも途中、鬼の動きがバグってるように感じたし、キャラDも動いて無かった気がしますm(__)m

という報告をいただいた回です。画面の症状を再現し、**同じ場所で二度と起きない**ように、
AIの「歩き方」そのものを作り直しました。ゲームのルール・速度・当たり判定・プレイヤーの
操作感・スイッチ／ゲート／階段は一切変えていません。

## 1. 実機の画面で見えていたこと

`ScreenRecording_11-17-2026 05-28-59`（3分の試合、`v0.7.3`、生存6 / 凍結0、1F⇄2F）を
8枚+24枚のフレームに切って確認しました。

- 2:47〜2:35 に2人が凍結→救出され、1:47 にプレイヤーが階段で1Fへ戻り、スイッチ3/3・ゲート開放。

D が「動いていない」のは気のせいではなく、**その場から一歩も進めない状態**に陥っていました。

## 2. コードを追って分かった原因（4つ、すべて同じ根っこ）

FROST LAB の1Fは「4つの部屋＋柱」で、部屋の出入り口は**南側の60pxの扉だけ**です
（`game.json` の `Wall` 44枚）。ところが v0.7.3 までのAIは、

1. **目標へ直進するだけ**で、壁は `SeparateFromObjects` に押し戻してもらう任せでした。
   目標が壁の向こうにあると「前進」と「押し戻し」が打ち消し合って**その場で停止**します。
2. 停止からの復帰は「ブロック検知→0.75秒の回避」だけで、しかも**人狼は検知のたびに
   回避する側を左右反転**していました（`previousSign ? -previousSign : random`）。
   同じ角で「左・右・左…」と振動する——これが**「鬼の動きがバグってる」**の正体です。
3. **ヒューマンCPUの回避方向は象限から決め打ち**（`(ay < 0 ? 1 : -1) * ...`）で、
   その角では毎回**壁の中を指したまま**でした。検知→同じ方向へ0.75秒→また同じ方向、で
   **試合が終わるまで1pxも動けない**——これが**「キャラDが動いていない」**の正体です。
4. v0.7.2 の「階段へ向かうコミット」は**パッド中心への直線**でした。扉の外にいる個体は
   最大6秒間その線を押し続け、`AiStairBound` の間は他の判断も止まるため、
   柱のそばで往復し続ける「トラム状態」になっていました。

## 3. 直したこと — `v0.7.4 AI 壁認識ステアリング`

`v0.6.1` のAIグループの**直前**に新しいJsCodeグループを1つ置き、両陣営（人狼・ヒューマン）が
同じ「歩き方」を使うようにしました。

1. **16pxナビゲーショングリッド（1F/2Fで88×88セル）** を起動時に1回だけ構築。
   壁44枚をセルに落とし、外周と床の切れ目も含めて歩けるマスを確定します。
2. **`__iceWolfV074PathDir`**: 目標セルから幅優先探索（BFS）し、`parent` をたどって
   **部屋の扉・柱の周り・階段まで実際に通れる道**を返します。直線が見えているときは
   探索せず直進（＝開けた場所での滑らかさは従来どおり）。再探索は**1個体0.5秒に1回まで**、
   目標が24px以上動いたときだけ。セル16pxは分離の押し出しと干渉しない粒度です。
3. **`__iceWolfV074Steer`**: 目標が見えていればそのまま、見えていなければ上の経路の
   次のセルへ。その上で
   - 16方向ファンで壁を回避。**回り込む側は「決めたら保持」**（毎フレーム決め直すと
     振動するため）。目標が見えたらリセット。
   - 壁の余白に**めり込んだ個体は法線方向へ歩いて出る**（`escapeStep`）。
   - **1.0秒まったく動けなければ0.7秒だけ別方向へ**（`unstick`）。これで「試合中ずっと
     立ち止まる」は構造的に起こりません。
4. **AI側の変更**は「目標座標を渡す」ことと「古い回避ロジックの削除」だけ。
   追跡・逃走・救助・スイッチ・階段・巡回の判断と速度（65/95/150/155/205 px/s）は不変です。
   階段の行き先は `__iceWolfV070StairToward` / `__iceWolfV072StairAway` が
   パッド中心（`tx` / `ty`）も返すようにして、経路探索の目標にしました。

プレイヤーの移動・カメラ・当たり判定・スイッチ／ゲート／階段の処理は**1行も変えていません**。

1. **JS構文**: 全65ブロック＋全40テストソース → **SYNTAX PASS**（`work/v074/syntax_v074.py`）。
2. **壁込みフレームシミュレーション**（`work/v074/sim_v074.py`、実イベントコードを

   3シナリオ × 2シード × 26秒 → **SIMULATION PASS**（上表）。
3. **新しいGDevelopテスト `v0.7.4 AI wall steering test`**（実ゲームのハーネスAPIで実行）:
   - 壁の向こうで凍結した味方の元へ**回り込んで解凍**する（中央の縦壁を越えて反対側へ渡る）。
   - 壁の向こうの獲物を人狼が**回り込んで凍結**させる。
   - 通常プレイ10秒で、**どのCPUも150フレーム（2.5秒）以上立ち止まらない**。
   ローカル再現（`work/v074/harness_v074.py`）→ **HARNESS PASS**。
4. **既存GDevelopテストの回帰**: `v0.6.1 Human CPU navigation recovery test` →
   **HARNESS PASS**。ここだけ、壁をすり抜けず正しい経路を通るぶん到着が遅くなるため、
   待ちフレームを 16→40回（5.3秒）に広げました（検証内容＝「目に見えて迂回する」「救助が
   完了する」は不変）。
5. **v0.7.2 階段ロジック**（`work/v072/sim_v072.py`）→ **SIMULATION PASS**、
   **v0.7.3 ブロックトイ**（`work/v073/sim_v073.py`）→ **ALL MOCK CHECKS PASS**（挙動不変）。
6. **iOSプロジェクト**: `python3 scripts/ios/verify-ios-project.py` → **ALL CHECKS PASSED**。
7. **負荷**: 7体ぶんのJSを quickjs（JITなし）で回して**0.76ms/フレーム**
