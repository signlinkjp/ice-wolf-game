# ICE WOLF v1.2.0 Build 37 — 6ステージの差別化・影オフ・凍結カメラ・造形向上

Build 36 を実機で遊んだトモアキさんの後半フィードバック 5 点への対応。

1. 遊園地モードで走ると影が出る → 要らない
2. 3ステージ遊んだが、ステージの形・2階への導線・ダッシュワープの位置が全部同じ
   → リリース時の世界観と演出・ギミックを分かりやすく
3. 凍らされた時の俯瞰カメラを自分中心にして、カメラワークだけを十字キー／スティックで
4. コンピュータ・ユーザーの動きや見た目、鬼・人狼・第3の人狼をすべて向上
5. 人狼・罠鬼・鬼も、役割が各自分かっているなら見た目は一緒でよい

## 1. 遊園地の影をオフ

`src/config.js` のステージ定義に `shadows` を持たせ、`park` だけ `false`。

- `src/render/view.js` の `setStage()` が `sun.castShadow` と `renderer.shadowMap.enabled`
  をステージごとに切り替える。遊園地では長い斜め影（壁やキャラの黒紫の影）が一切出ない。
- 足元の小さな丸影（`blobShadowTexture`）は残す。接地感はそのままで、影だけが消える。
- 他の5ステージは従来どおりソフトシャドウを維持。

## 2. 6ステージを本当に別のステージに

これまで 2F は「x ≥ 6 の東半分」で固定、階段・ワープ・ダッシュ・スイッチ候補・ゲートも
全ステージ共通だった。Build 37 では **ステージごとに 2F の矩形（`stage.deck`）を宣言**し、
そこから共有フレームを導出する形に作り直した。

| ステージ | 2F の形 | 2Fへの導線（階段） | ワープ |
| --- | --- | --- | --- |
| classic | 東半分（18×36） | 西辺 x=6 の南北2か所（東へ上がる） | 南の氷 → 北東のデッキ |
| aquarium | 中央の島（16×20） | 島の西辺（東へ）と東辺（西へ）— 堀を回って登る | 南西の氷 → 島の中央 |
| park | 北側バルコニー（40×12） | 南辺 z=-6 の東西2か所（北へ上がる） | 南東の氷 → バルコニー東端 |
| lodge | L字（大広間＋東の別館） | L の西辺 x=0 と別館の西辺 x=12 | 南西の氷 → 大広間の北 |
| school | 上下2分割（北教室・南教室） | 中央廊下 z=0 から北教室・南教室へ1本ずつ | 西の廊下 → 南教室の東 |
| space | リング（北帯・南帯・東の背骨） | 中央コートから北帯・南帯へ1本ずつ | 西の中央 → 東の背骨 |

- `src/core/geometry.js` を全面改修。`stage.deck` の矩形から
  「1F の外周壁」「2F の外周壁（デッキが届く範囲だけ）」「デッキの縁（1F は崖・2F は手すり、
  階段の所は切り欠き）」「2階層ナビゲーショングリッド」を自動生成する。
- 判定は位置ではなく**面**で決まる：`insideDeck(stage,x,z)` が真なら 2F、偽なら 1F。
  `isWalkable()` もデッキの内外を検査するので、1F の人がデッキの下に潜り込むことはない。
- スイッチ候補・スポーン・ゲート・パッド・ワープは全ステージで書き直し、
  `snapFloor()`（実際に立っている面で階を確定）と `openSpotFor()`（壁の中なら最寄りの空きへ）
  を通す。`npm test` が全ステージで階段昇降・壁判定・到達性・クリアランス 1.2 m を検証する。
- ダッシュパッドは各ステージ 2F/1F に2個ずつ、位置をすべて入れ替えた。
- 2F の床はステージのアクセント色を34%混ぜた色にした。1F と色が違うので、
  どの角度から見ても「どこが2階か」が形として読める。
- ゲートは各ステージ3か所（1F 西・1F 北/南・2F）。`facing: 'south'` を追加。
- CPU（`src/core/ai.js`）と宇宙の高重力セル（`src/core/rules.js`）は
  `randomPointOn(stage, floor, rng)` でステージの矩形から目的地を引くようにした。

### 2b. 階段とCPUの導線（Build 37 で直した3点）

1. **階段は「上る向き」で乗る**。これまでは階段の足元 1.5 m 以内に入れば乗れたので、
   廊下の途中に階段口がある学校では、廊下を横切るだけで2階に上がってしまった。
   `stepStairs()` は踏み口（デッキの縁から 1.35 m 以内・幅の内側）にいて、
   しかもデッキ方向へ進んでいる時だけ昇降する。降りる側は逆に「縁へ踏み出す」時だけ。
2. **CPUは他階のスイッチも狙う**。`nearestBy()` は同じ階のものしか返さないため、
   2階にしか残っていないと誰も取りに行かなかった。同階に無ければ最寄りの他階スイッチへ
   階段／ワープで向かう。1分間のシミュレーションで全6ステージ・全シードで
   2階スイッチが起動することをテストで固定した。
3. **経路の再計算でウェイポイント番号をリセット**。0.9秒ごとの再探索で `ai.wp` が
   古い経路のまま残り、学校の廊下前で前後に往復する取りこぼしがあった（既存バグ）。

## 3. ステージの世界観とギミックを一目で分かるように

`src/render/stage3d.js` に `makeShow(stage)` を追加。ギミックごとに「動く主役」を1つ置いた。

- **aquarium**：巨大なマンタが水槽の上を泳ぐ。マンタの時間（27秒周期・3秒）は旋回と泡が増える。
- **park**：パレードの山車が2階バルコニーを往復する。パレード中（16秒周期・5秒）は加速し、
  弾む。観覧車・屋台・電飾はそのまま。
- **lodge**：吹雪の時間だけ、斜めに走る雪（260粒）が視界を横切る。
- **school**：中央廊下と2Fの扉の上にチャイム灯。予告で琥珀、閉鎖中は赤、平常は灰。
  鉄扉そのものは従来どおり閉鎖中だけ出現。
- **space**：高重力セルの6か所にリング。予告で紫、発動中は赤に変わる。

## 4. 凍結中は自分中心カメラ＋スティックで見回す

- 自動で他のキャラへ切り替える処理を廃止（`main.js` の `updateHud` から自動 spectate を削除）。
  凍った瞬間から、カメラは**凍った自分の真上**の俯瞰。
- スティック（または矢印/WASD）を倒すと、キャラは動かず**カメラの注目点だけ**が滑らかに移動する
  （最大 ±18 m / ±16 m、速度 13 m/s）。`applyFrozenPan()` → `view.panFrozen()`。
- `CAM` ボタンで自分中心に戻る。救助されて凍結が解けると、オフセットは自動で 0 へ戻る。
- 観戦バーの `‹ ›` は、氷に残っている仲間へカメラを飛ばすボタンとして残した。
  バーの文言は「スティックで視点移動・CAMで自分中心」。
- 凍結中のヒントも「凍った！仲間の救助を待ちながらスティックで見回せる」に変更（12言語）。

## 5. キャラクターの造形と動き

`src/render/actors3d.js` を書き直した。

- **役職は見た目に出さない**：人間・人狼鬼（人間状態）・罠で生まれた第3の鬼は、同じ体・同じ服。
  自分の識別は**足元の金のリングと金のネームタグだけ**（服の色はステージ色で全員共通）。
- **造形**：丸みのある頭・ニット帽（ブリムとポンポン付き）・白目＋瞳＋ハイライトの目・眉・口・
  襟・リュック・手のひら。トルソーとリュックは角を落とした形状（`roundedBox`）。
  帽子はステージ色で全員共通なので、役職の手がかりにはならない。
- **走り**：脚と腕の振りを大きく（±1.0 rad）、体の前傾 0.18、上下バウンス、左右の揺れ、
  着地のスクワッシュ、頭の向き、足元の雪煙。走行中の口は開く。
- **鬼（人狼モード／マスター鬼）**：頭の赤いツノと耳、赤く光る目、首元の赤いリング、
  **頂点アニメで翻る赤マント**、足元の赤リング。走りは前傾 0.3 の突進姿勢で速い。
