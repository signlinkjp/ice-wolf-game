# ICE WOLF v1.1.0 — 5ステージの本格ビジュアル（テクスチャ・3D小道具・空気）

Build 16 の深海水族館は「FROST LAB に青い色を掛けただけ」に見えました。PRO 500円の
価値は「別の場所で遊べること」なので、v1.1.0 の5ステージは**それぞれが自分の
壁・天端・床のテクスチャ**と**自分の3D小道具**と**自分の空気（フォグ・空の色）**を
持ちます。クラシック（FROST LAB）は 1.0.0 のままです。

## 2. 仕組み（`v1.1.0 ステージ・衣装` の2つ目のイベント）

1. ステージが変わった瞬間だけ動きます（毎フレームの処理はゼロ）。
2. `Wall` の前・後・左・右の面に `wall_<stage>.png`、上・下の面に `cap_<stage>.png` を
   `setFaceResourceName` で貼り、`setTileScale(0.3125)` で、高さ160pxの壁面にちょうど1模様（512pxのテクスチャ1枚ぶん）が収まるようにします。
   `Floor` は6面とも `floor_<stage>.png`、`setTileScale(0.5)`。
3. 壁の上（z = 壁の高さ）に小道具を置きます。**床には何も置かない**ので、小道具が
   プレイヤーの進路を塞ぐことはありません。
   - 外周の8枚の壁：`border` キットを長さに沿って等間隔（2〜4個）
   - 内側の壁：そのステージが使う寸法だけ（例：90×90 の柱→水槽柱、320×32→暖炉）
   - 12枚の待避中の壁（y = 40000）は触りません
4. 小道具は**素材ごとに1メッシュへ合成**します（不透明＋発光の2メッシュ＝2ドロー
   コール）。頂点は数千規模で、iPhone では無視できる負荷です。
5. `THREE.Fog` と `setBackgroundColor` で空気を入れ替えます。
6. クラシックへ戻すときは、フロストラボのテクスチャ・タイル倍率・空気を元に戻します。

### 上下が入れ替わっても大丈夫なように

GDevelop の Cube3D は、壁の2つの広い面のうち片方でテクスチャの v が反転します
（`Cube3DRuntimeObjectPixiRenderer.updateTextureUvMapping`）。どちらが反転するかは
エンジン側の都合で決まり、実機で確かめるまで分かりません。そこで壁のテクスチャは
**中央線で上下対称**に描いてあります（砂と珊瑚は上下の両端、幕と電球も両端、
腰壁は上下、黒板と窓は中央）。どちら向きに貼られても「逆さまだ」と分かる絵に
ならないので、見た目が壊れません。

## 3. テクスチャの生成

    python3 tools/make_stage_textures.py

`assets/` に 15枚（5ステージ × 壁/天端/床、各 512×512）を書き出します。
すべて継ぎ目なくタイルし、256色に量子化してあります（合計 ≒ 550KB）。
乱数の種は固定なので、何度実行しても同じバイト列になります。
水面のコースティクスと雪の風紋は、整数周波数の sin の和なので、タイルの端で
必ずつながります。

## 5. 触っていないもの

移動速度・当たり判定・凍結/救助・スイッチ/ゲート・階段・ワープ・スピード床・AI・
カメラの距離は 1.0.0 の数字のままです。壁は**動かすだけで、サイズもテクスチャの
当たり判定も変えません**。`tests/pro/scope-guard.test.mjs` が 1.0.0 のアセット・
イベント順・数値を毎回突き合わせます。

`npm test` の `tests/pro/v110-visual.test.mjs`：

* 5ステージの平均色が、クラシックからも互いからも十分に離れている（別の場所に見える）
* 芸術ブロックが6ステージすべてで例外なく走り、壁6面・床・タイル倍率・フォグ・

* 小道具は必ず壁の上（z ≧ 160）にあり、床には一つも無い
* ステージが変わらないフレームでは何も作り直さない
* SETTINGS のカメラ行が日本語で、12言語すべてに存在する

# Build 18 — 紫の「G」を消し、水族館に魚を泳がせ、床を落ち着かせる

## 1. 何が起きていたか（Build 17 の紫の G）

`setFaceResourceName(face, 'wall_aquarium.png')` は**名前を付けるだけ**で、gdjs は
その瞬間に画像マネージャが持っているものから面の material を作ります
（`Cube3DRuntimeObjectPixiRenderer` → `ImageManager.getThreeMaterial` →
`getThreeTexture` → `getPIXITexture`）。まだ読み込んでいない名前に対しては
`_invalidTexture`（紫の G の 192×192 画像）を返し、しかも**その名前でキャッシュ**します。

そして gdjs がシーン開始時に先読みするのは、そのシーンの `usedResources`
（＝オブジェクトのデータやイベントのリソース欄から機械的に拾ったもの）と
`projectData.usedResources`（プロジェクト直下のオブジェクト）だけです。
v1.1.0 の15枚は JavaScript から名前で貼るだけなので**どの一覧にも載らず**、
一度も読み込まれないまま面に貼られ、全ステージの壁と床が紫になっていました。

`resources.resources[].alwaysLoaded` は**実行時には読まれません**
（GDJS のランタイムに `alwaysLoaded` を参照する箇所はなく、書き出し側も
`usedResources` は「プロジェクト直下のオブジェクト＋拡張機能のイベント」から作ります）。
ですから `alwaysLoaded: true` を付けても直りません。

## 2. どう直したか

`v1.1.0 ステージ・衣装` の2つ目のイベント（芸術ブロック）に「読み込みの門」を置きました。

1. ステージを塗る前に、そのステージの3枚（wall / cap / floor）が
   `ImageManager.getPIXITexture(name)` で**本物のテクスチャ**を返すか確認します
   （`getInvalidPIXITexture()` と同じなら「まだ無い」）。
2. 無ければ `ImageManager.loadResource(name)`（ゲーム自身のローダー）で読み込み、
   Promise が解決したら `_loadedThreeTextures` / `_loadedThreeMaterials` の
   その名前のキャッシュを捨てます（早く貼ってしまった紫を残さないため）。
3. 3枚とも揃ったフレームで初めて `setFaceResourceName` を呼びます。揃うまでは
   1.0.0 のフロストラボ面（必ず読み込まれている）をそのまま見せます。
   この間 `StageArtPending` にステージidが入ります。
4. 9秒待っても来なければ、そのステージの空気・小道具・魚だけを載せ、面は
   フロストラボのまま（`StageArtMode = 'fallback'`）。**紫は絶対に出しません。**
   遅れて届いた場合はその場で本物のテクスチャに貼り替わります。

CI 側でも `ios-testflight.yml` の `EXPORT_ASSETS` に15枚を足し、書き出しに
1枚でも欠けたらジョブを落とすようにしました（JavaScript から名前で貼る
リソースは、書き出し側の依存関係の解析からは見えないため）。

## 3. 水族館：水と魚

* 壁：明るいアクアのガラスパネル。色とりどりの魚5匹、クラゲ2匹、珊瑚の茂み、
  海藻、気泡の筋、水面のコースティクス、真鍮色のさん（mullion）。
* 天端：明るい水面のコースティクス＋上から見た小魚2匹。
* 床：砂床の落ち着いたタイル。大きな光の帯だけで、細かい模様は入れません。
* **泳ぐ魚**：外周の壁の内側を回るリング（1Fの床から26px内側）を、
  魚の群れ2つ（6匹＋4匹）とクラゲ3匹がゆっくり周回します。壁の天端（160px）より
  50〜130px 上、プレイ床の外なので、カメラとキャラクターの間に入りません。
  群れ1つ・クラゲ1匹はそれぞれ**1つの合成ジオメトリ**（頂点カラー）なので、
  群れ全体で5ドローコール。1フレームの処理は 5つの mesh の
  position / rotation / scale を書くだけです。当たり判定・ゲームオブジェクトには
  一切触れません。

## 4. 視認性（全ステージ）

* **床**：ローカルコントラストを 15〜25 レベルまで落としました（遊園地の
  白黒市松＋紙吹雪、廃校の大きな染み、宇宙船の黒いスリットなどを廃止／減衰）。
  プレイヤー・ラベル・氷・スイッチ・救助リングが床から浮き上がります。
* **壁**：宇宙船の壁・天端、ロッジの床、廃校の床を持ち上げ、暗い継ぎ目を細く。
* **フォグと空**：全ステージでフォグ色を明るく、`fogNear/fogFar` を奥へ。
* **雰囲気オーバーレイ**：各ステージの暗幕（とくに宇宙船 .40、遊園地 .44）を
  薄くしました。

## 6. Build 20 — 霧の遊園地の作り直し

トモアキさんから「霧の遊園地は画面見づらい／説明の文字が読みづらい／違う演出がほしい」と
の要望があり、遊園地だけを見た目から作り直しました。他の4ステージは Build 19 のままです。

* **壁**：4色（クリーム／ピンク／紫／橙）の縞＋スカラップの裾をやめ、深いプラムの
  プリーツ4枚＋細い金の筋＋控えめな電球列に。160px の壁面に縞が8本入っていたため
  画面端が「縦縞のカーテン」に見え、白いHUD文字が読めなくなっていました。壁を暗く
  静かにしたことで、HUDの白文字がそのまま浮きます。
* **天端**：ピンクの放射縞をやめ、プラム2色＋クリームの縫い目＋電球に。
* **床**：紫グリッド＋星をやめ、温かい木の板張り（2色の差は14レベル、継ぎ目だけ）。
  遊園地の衣装は濃い紫なので、明るい床でキャラクターが浮き上がります。床の模様は
  床テクスチャに焼かず、3Dの光の輪（`iceWolfV111Pool`）として置いています。
* **小道具**：テントをクリーム＋コーラルの裾に、屋台をプラムに統一。新しく
  `balloon`（風船3つ＋重り）を追加し、**観覧車を左右の壁の上に1基ずつ**、
  **風船を南の壁に3束**置きました。すべて境界の壁の上で、プレイ床には置きません。
* **空気**：フォグを `0x3c2559` → `0x6a5878`（薄紫）に。明るい床が遠くで黒く沈まない
  ようにしました。
* `tools/make_stage_textures.py` の `build_park_wall / _cap / _floor` を作り直し、
  `assets/wall_park.png` ほか3枚を再生成（他の12枚はバイト単位で不変）。

テスト（`tests/pro/v111-gimmicks.test.mjs`）：床のローカルコントラストが46レベル未満で
明るさ120以上であること、観覧車と風船が公園専用の小道具として置かれること。
