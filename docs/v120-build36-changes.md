## 1. 音が聞こえなくなる（`src/audio.js`, `src/main.js`）

原因は iOS の WKWebView で、`AudioContext.resume()` だけでは音声セッションが
開かないことがある点と、Build 35 が画面を隠すたびに `suspend()` していた点です。

- `unlock()` で `ctx.resume()` に加えて **無音の1サンプルバッファを再生** するようにしました
  （`createBuffer(1, 1, 22050)` → `BufferSource.start(0)`）。WKWebView は実際に
  バッファが鳴ったときだけセッションを開くためです。
- `suspended` / `interrupted` のどちらでも `resume()` を試します。
- `tone()` / `noise()` / `music()` は、鳴らす前に `ctx.state !== 'running'` なら
  `resume()` を試します（電話・バックグラウンドから戻ったあとの自動復帰）。
- `visibilitychange` での `suspend()` を **やめました**。復帰時と `pageshow` のときだけ
  `resume()` します。自分で suspend した Context を iOS が再開しないことがあるためです。
- `main.js` の初期化で **ホーム画面を含む最初の `pointerdown` / `touchstart` / `keydown`
  で一度だけ `audio.unlock()`** を呼ぶグローバルリスナーを入れました。
  `{ passive: true }` なので、タップを奪うことはありません（Build 33 の
  「ボタンのタップが移動に吸われる」不具合の再発防止テストも、この1本だけを許可する形に更新）。

## 2. 起動したら英語スタート（`ios/App/App/Info.plist`, `src/i18n.js`）

- `Info.plist` に **`CFBundleLocalizations`（12言語）** を追加しました。これがないと
  WKWebView は日本端末でも `navigator.language` を常に `en-US` と返します。
- `i18n.detect()` を、`navigator.languages` の配列全体を順に見る方式に変更。
  さらに **どのタグも英語しか名乗らず、端末のタイムゾーンが `Asia/Tokyo` の場合は
  `ja`** を返すフォールバックを追加しました（設定で言語を選んだ `localStorage` がある場合は
  それが最優先）。
- `verify-ios-project.py` に「12言語の `CFBundleLocalizations` がある」チェックを追加。

## 3. 通知の分離：自分＝上中央、コンピュータ＝左上（`src/main.js`, `src/ui.js`, `styles.css`, `index.html`, `src/i18n.js`）

Build 35 は、CPU が起こした凍結・スイッチ・救助まで画面中央のトーストに出ていました。
自分の操作の結果と他人の動きが混ざり、視界も塞いでいたため分けました。

| 出来事 | 自分の関与 | 表示 |

| 凍結 | CPU/他人どうし | 左上ログ「A が B を凍らせた」 |
| 救助 | 自分が救助／自分が助けられた | 中央「救助した！」／「解凍された！」 |
| 救助 | CPU/他人どうし | 左上「C が D を救助」 |
| スイッチ | 自分 | 中央「スイッチ起動！（n/t）」「ハズレのスイッチ」 |
| スイッチ | CPU/他人 | 左上「B: スイッチ起動（1/3）」「B: ハズレのスイッチ」 |
| 罠 | 自分 | 中央「罠スイッチ！人狼鬼になった」／「罠の氷だった！…」 |

| 指名 | CPU | 左上「A: 凍った人間を指名」 |

- 左上ログ `#cpuLog` は HUD カードの下・左上寄せ。**最大3行**で、1行ずつ約2.8秒で
  自動フェードアウト。色（青／緑／橙／赤）は出来事の種類だけを表します。
- 中央トーストは従来どおり上中央（`top: 25%`）で、自分の結果専用。
- いまのオンライン実装は「ローカル席＝0」で動いているため、席の対応は 0 を自分として扱います
  （ゲスト側の席番号の割り当ては今後の課題。§6参照）。

## 4. マスター鬼・人狼鬼の指名・3人目ルール（`src/core/rules.js`, `src/core/ai.js`, `src/ui.js`, `src/i18n.js`）

- `infectFrozen()` は **`firstWolf`（マスター鬼）だけ** が成功するようにしました。
  2人目の人狼鬼と、罠で生まれた3人目は指名できません（CPU の AI も同じ条件）。
- 3人目の鬼は **罠（罠スイッチ／罠の氷の救助）でしか生まれない** ことを、
  遊び方（`how.p8`・新しい `how.p9`）と開始ブリーフィング（`brief.wolf`・`brief.werewolf`）に
  12言語すべてで明記しました。
- HUD の役割表示は `マスター鬼 / MASTER WOLF` に変更（`role.wolf.label`）。
- 指名ボタンは **マスター鬼が人狼モード中のときだけ** 表示（`ui.updateHud`）。
- 遊び方は8行 → 9行に増え、マスター鬼の指名の説明が独立した1行になりました。

## 5. ステージの視認性（`src/render/stage3d.js`）

氷（白〜水色）と同化していた4種を、ステージの配色に関係ない「意味の色」で描き直しました。

- **スイッチ（アンバー／ゴールド）**: 黒に近いブロンズの台座＋金のリング＋太い柱＋
  大きなアンバーのランプ＋輪＋光の柱。未起動は黄金色に発光、起動成功は **緑**、
  ハズレ／罠で作動済みは **暗いグレー** に変わります。床にも金のリングを敷きました。
- **出口ゲート（EXIT）**: 濃紺の枠＋金の縁取り＋**赤いバリア扉**＋赤い警告ランプ＋
  床の赤リング。開放すると扉が床に沈み、**エメラルドの光・緑のランプ・緑の床リング**、
  そして **「EXIT」プレートが緑** に変わります。プレートは表裏の両面にあり、
  上端には色付きのライトバーを付けたので、真横からでも開閉が分かります。
- **ワープ（マゼンタ／バイオレット）**: 二重リング（逆回転）＋中心の円盤＋
  上昇する光の柱＋外周のオーラ＋螺旋状に昇る光の粒。どのステージでも紫系は
  ワープだけなので、氷ともスピードパッドとも混同しません。
- **階段（温色の木）**: 木目の踏板＋明るい縁取り＋側面の縁板＋足元の2本の
  アンバーの矢印とリング＋2F側のリング。踏面を deck の外側に寄せ、
  **デッキの中に埋まらず全体が見える** ようにしました。入口には光るキャップの
  ボラードを2本立てています。
- **おまけの修正**: Build 35 は「スイッチ候補13か所すべて」を描いていて、実際には
  試合に存在しないスイッチまで光っていました（本物がどれか分からない原因）。
  試合中の候補地は、**その試合に実在するスイッチだけ** を表示するようにしました。
  また罠スイッチだけ色が違って見える（＝バレる）状態も直しました。
